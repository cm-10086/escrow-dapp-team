# 订单时间线

路线 B 的订单时间线在 `/escrow` 的订单行中展开显示。功能沿用现有测试网 Escrow，不需要部署新合约、配置私钥或再次创建验收订单。

## 使用与截图

1. 启动项目后打开 `/escrow`，等订单列表加载。
2. 在订单 #7 的操作列点击“展开时间线”，等待时间和操作账户读取完成。应看到创建订单、付款入托管、确认收货并放款三条记录。
3. 展开订单 #8，应看到创建订单、付款入托管、发起争议、仲裁退款给买家四条记录。
4. 点击任一完整交易哈希，在浏览器中核对详情。可通过“刷新时间线”重试读取；收起后再次展开会复用缓存。
5. 分别保存正常成交与争议退款时间线截图，在报告 4.5 下新增“订单时间线”一节，并写明订单号、操作成员与截图归属。截图应保留实际读取的时间、区块与交易信息。

未连接钱包也可以读取时间线。读取时间线本身不会触发钱包签名或链上交易。授权发生在代币合约中，Approval 没有订单 ID，因此本功能展示 Escrow 的订单生命周期事件，不将额度授权伪装成某笔订单的独立事件。

## 读取与完整性

- 列表把 OrderCreated 的真实创建区块传给订单行。新创建订单在成功回执解析出 ID 时也同时传入回执区块，不必等全量历史同步。
- 展开时读取订单当前状态，从创建区块按每批 10 区块查询六种 Escrow 事件，并按真实 ID 筛选。缓存键包含网络、合约、区间和订单状态，不混用不同合约的数据。
- 去除重复、移除的和未确认的日志，按 blockNumber、transactionIndex、logIndex 排序。同一笔交易中的不同日志分别保留。
- 普通成交要求 Created、Paid、Completed；仲裁结束要求 Created、Paid、Disputed、Resolved，并根据 sellerWins 区分放款和退款；超期退款使用真实 Refunded 事件。
- 找到当前状态的目标事件后停止继续扫空区块，但若缺少前置事件仍提示不完整。失败批次不会被当成成功的空记录。
- 未结束订单在展开期间定期更新，也随订单状态刷新；已结束订单复用缓存。收起时取消后续时间线扫描。区块时间和交易账户查询单独缓存、单独重试。

订单列表补充了可选的区块浏览器索引加速：仅从成功的 createOrder 调用中提取候选区块，再逐块用 RPC 验证实际创建事件。索引不能直接提供订单 ID，也不能作为完整性结论。索引不可用或只覆盖部分记录时，原有历史补读继续工作；索引加速最多读取三页，避免无限抓取浏览器数据。

## 验证

运行 `yarn workspace @se-2/nextjs test:timeline`，包含 12 项生命周期读取测试和 3 项候选区块校验测试。原有写操作、事件批次、角色汇总和权限测试同时通过，共 48 项；前端 TypeScript 与 lint 通过，CI 已加入时间线测试。

隔离浏览器覆盖未展开不请求、跨大区间首次加载、不同订单隔离、正常成交和两种仲裁结果、区块时间失败重试、完整性提示、事件读取失败重试、状态变化、缓存复用、索引故障回退、10 区块限制和手机布局。模拟测试数据不作为报告中的真实交易或截图。

真实只读核验确认 #7 与 #8 的事件顺序、上述七个交易哈希和历史区块时间。该次核验没有发送新交易，也没有改变订单或合约。

## 报告说明参考

本组在订单页面中增加了可展开的订单时间线。系统读取 Escrow 的真实事件日志，按照区块号、交易位置和日志位置排序，逐条展示操作类型、区块时间、操作账户和交易哈希。正常成交订单 #7 展示创建、付款、确认收货三条记录，争议退款订单 #8 展示创建、付款、争议和仲裁退款四条记录，均可通过交易链接在区块浏览器核验。时间线采用按需查询、每批最多 10 个区块和缓存机制；读取失败或事件不完整时显示提示，不使用推测内容补齐链上记录。
